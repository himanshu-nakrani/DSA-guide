## 2024-06-13 - HMAC Timing Attack in Session Parsing
**Vulnerability:** The `parseSessionValue` function in `src/lib/auth.ts` was using a simple equality operator (`!==`) to compare the expected HMAC signature against the provided signature. This allows an attacker to perform a timing attack by measuring the time it takes for the comparison to fail, byte by byte, eventually forging a valid signature.
**Learning:** Even if the underlying hashing algorithm (like SHA256) is secure, the comparison of cryptographic signatures must always be done in constant time to prevent side-channel timing attacks.
**Prevention:** Always use `crypto.timingSafeEqual` (or a similar constant-time comparison function) when comparing cryptographic hashes, signatures, or MACs.
## 2024-06-21 - [Authentication Bypass due to Unawaited Async Function]
**Vulnerability:** In `loginAction`, the `verifyPassword` function was called without an `await` keyword. Because it returns a Promise, `!verifyPassword(...)` always evaluates to `false`, causing the system to accept any password for a valid email.
**Learning:** When refactoring synchronous cryptography/authentication functions to be asynchronous (e.g., switching from `scryptSync` to promisified `scrypt` to avoid blocking the event loop), all call sites must be updated to use `await`. If missed, the returned Promise evaluates to truthy, potentially bypassing critical security checks completely.
**Prevention:** Enable and enforce strict TypeScript/ESLint rules for unhandled Promises (e.g., `@typescript-eslint/no-floating-promises` or `@typescript-eslint/no-misused-promises` where applicable). Always write unit/integration tests that attempt authentication with incorrect passwords to catch such bypasses.
