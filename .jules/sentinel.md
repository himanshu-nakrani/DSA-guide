## 2024-06-13 - HMAC Timing Attack in Session Parsing
**Vulnerability:** The `parseSessionValue` function in `src/lib/auth.ts` was using a simple equality operator (`!==`) to compare the expected HMAC signature against the provided signature. This allows an attacker to perform a timing attack by measuring the time it takes for the comparison to fail, byte by byte, eventually forging a valid signature.
**Learning:** Even if the underlying hashing algorithm (like SHA256) is secure, the comparison of cryptographic signatures must always be done in constant time to prevent side-channel timing attacks.
**Prevention:** Always use `crypto.timingSafeEqual` (or a similar constant-time comparison function) when comparing cryptographic hashes, signatures, or MACs.
## 2025-02-20 - Authentication Bypass Due to Un-awaited Async Function
**Vulnerability:** A critical authentication bypass was found in the login endpoint (`src/app/auth/actions.ts`). The login action called `verifyPassword` without `await`, passing the truthy Promise object directly into an `if (!verifyPassword(...))` check, which always evaluated to `false`. This meant any password could bypass verification as long as the user email existed.
**Learning:** This occurred because `verifyPassword` was recently refactored to be asynchronous (likely to use `scryptAsync` and avoid blocking the event loop) but the caller was not updated. Changing a synchronous security function to asynchronous without auditing all call sites can introduce severe bypass vulnerabilities due to JavaScript's truthy Promise evaluation.
**Prevention:** Always audit call sites when converting authentication or authorization functions from synchronous to asynchronous. Strongly type boolean-returning security functions and rely on TypeScript rules (e.g., `no-floating-promises` or stricter boolean checks) to catch un-awaited Promises in conditionals.
